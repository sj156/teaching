# Create Homework: layout

Apply these standards within the scope selected in [SKILL.md](../SKILL.md). This reference does not initiate a separate review pass or expand the task.

## Make the mathematics inviting to read

Use the course’s existing LaTeX style and inspect its interface before authoring. If the project supplies `myHW.sty`, reuse its metadata, task, point, and hint commands. This repository does not distribute `myHW.sty`; otherwise use the project’s equivalent environments or a minimal standard layout. Preserve shared styles and make assignment-specific adjustments locally. Do not inherit unrelated course metadata or invent deadlines.

Make the rendered homework look polished, not merely compilable: use the shared typography and colors consistently, align point labels, keep hints visually distinct, and balance spacing around models, tasks, and page breaks. Inspect every final page for crowded equations, stranded headings or hints, uneven whitespace, and overflow. Fix layout without shrinking the text or imposing an arbitrary page count. Keep task text prominent and hints legible in print.

Display central models, integrals, and identities. Use proper fractions and sized delimiters where they improve readability; avoid cramped slash-heavy formulas and oversized nested fractions. Align related expressions when that clarifies their relationship. Split crowded lines rather than shrinking the text.

Separate setup, tasks, equations, and hints with enough space to scan. Avoid orphaned hints, stranded headings, clipped equations, and almost-empty overflow pages. Do not make the homework look like an exam with large answer spaces unless requested.

For LaTeX/PDF work, use the available compilation and PDF workflows. Compile, inspect diagnostics, render pages, and visually check the final revision. Check the actual final files in the user's chosen folder. Prefer fixing layout over forcing a page count.
